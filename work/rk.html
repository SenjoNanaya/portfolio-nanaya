Context

Stock-exchange disclosures can be difficult to screen. Figures appear in HTML filings and annual-report PDFs, with amounts stated in thousands, millions, or billions. Missing a scale note can distort the resulting calculations.

I built this as a personal project to turn those filings into screening metrics: 12+ indicators per company, a watchlist, and multi-ticker comparison, served through a web API with a registry front end.

Constraints

  • Personal and educational research only. The numbers still need checking against the filings.
  • The hosted demo is offline, so the registry must run from the repository with a one-command demo.
  • Filings state amounts in thousands, millions, or billions; the parser must apply the stated multiplier.

What I did

As the only builder, I wrote the full pipeline: a Python scraper for 238 HTML filing pages, PDF ranking for 2,264+ disclosure PDFs covering 200+ listed companies, SQLite storage with filing-backed figures, a Django REST API, and a React registry with 12+ screening metrics, watchlist, and compare.

Key decisions

  • Used filing-backed figures where available and labelled incomplete data; some missing fields can also be derived from other figures.
  • Ranked PDFs to fill named fields only, instead of trusting every extracted number.
  • Kept screening thresholds adjustable in the interface, with unset checklist defaults, so a screen can be re-run without rescraping.

Verification

Fixture suite checks fixtures/parser/ scale-note fixtures (thousands and millions cases), an EDGE layout canary, and screening guards via python scripts/run_fixture_tests.py. No EDGE calls. When a filing says amounts are in millions, a parser test fails if the wrong multiplier is applied.

Result

The registry provides 12+ screening metrics, a watchlist, and multi-ticker comparison. The pipeline scraped 238 HTML filing pages and ranked 2,264+ PDFs for 200+ listed companies; a one-command demo uses a sample database.

Limitation

The hosted demo is offline; run the one-command demo from the repository. This project ranks disclosure PDFs; it did not parse every PDF fully. It does not prove any figure is correct: personal and educational research only, and numbers still need checking against filings.

What I would do next

  • Spot-check a sample of computed ratios against the source filings and record the misses.
  • Extend the layout canary so EDGE markup changes fail loudly instead of silently.
  • Write down the demo restore steps before relying on the hosted link for any deadline.
